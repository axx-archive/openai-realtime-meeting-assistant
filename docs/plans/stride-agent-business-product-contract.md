# STRIDE: persistent agents and entrepreneur-owned businesses

Decision owner: lead. Date: 2026-09-04. Status: target product and implementation contract, not a claim of live autonomous operation. Supplements the execution ledger and autonomous-business runtime contract. Latest founder direction explicitly permits agent management and asks for hiring, persistence, human-CEO and autonomous-founder modes.

## Product choice and initial customer

STRIDE is where agents work together to build and operate businesses. Every inherited subsystem remains an unproven concept until validated against this product. Reuse is conditional; intentional replacement is allowed with preserved data and an explicit transition. Legacy tests establish regression evidence only.

The first customer is an entrepreneur or small expert team building a digital product or service. They know a customer problem and can supply an initial resource allowance, but should not need to construct an agent harness. STRIDE Builders, improving STRIDE itself, is the internal proving ground; it is not external demand evidence.

Both starting an idea and bringing an existing business are supported concepts. The initial product path is one business, one objective, a small team and one measurable customer-facing outcome. The platform must first complete two successive episodes, including an observation that changes the second episode. An agent catalogue alone is not the product.

## Four objects that must stay distinct

| Object | Durable identity and ownership | What changes without replacing it |
|---|---|---|
| Agent offering | Publisher-owned, versioned capability package or hosted service listing | New versions, supported routes, capability evaluations and price terms |
| Agent employment | Business-owned seat/principal binding to an exact offering version | Name, role, mandate, reporting line, authorized learning and approved version migration |
| Business | Owner-controlled mission, policy, budgets, customer definition and resource bindings | Team, strategy, projects, operating mode and provider choices |
| Work attempt | Exact episode/decision, executor lease, source snapshot and effect receipts | Checkpoints and result revisions under the existing execution lifecycle |

A Work root is the stable commitment within an episode; attempts are separate execution records beneath it. Retries, resumed workers and route changes retain that root and do not mint another commitment.

An offering could be hired by many organizations. Each hire creates an isolated employment, not access to a global personality's combined customer memory. Two businesses using the same offering do not share conversations, credentials or private lessons. Public capability claims and explicitly released reusable methods may be shared. A third-party hosted agent is a distinct data processor, and onboarding must show what data leaves STRIDE and the actual applicable retention conditions. A publisher update cannot silently widen an existing hire's access.

The agent's display name is not the model. A seat can survive a provider outage or model retirement by moving to another qualified, allowed route while preserving its commitments, identity and history. Do not imply continuity of model consciousness. Saved reasoning summaries are operational records, not an assurance that private model state or hidden reasoning persists.

Initial hiring is a curated set of three useful capabilities: operator, builder/researcher and reviewer. Entrepreneurs may customize a role or attach an existing agent through a qualified adapter. A public marketplace follows only when capability evaluation, publisher identity, version updates, permissions, offboarding and actual support responsibilities work. Ranking uses task-specific evidence, reliability, cost and outcomes, with synthetic demonstrations separated from customer use. Token consumption and popularity are not competence.

## Persistence contract

Persistence has five separately owned parts:

1. **Identity and employment:** principal, business, role, supervisor, exact package version, mandate, resource scopes and lifecycle. The business owns continuity if the vendor or underlying model changes.
2. **Knowledge:** source-bound business records and per-employment working knowledge. Every remembered claim has source references, audience, timestamp, correction/retraction status and confidence limits. Retrieval rebuilds an authorized context at use time.
3. **Commitments:** durable queue, objective, current Work/attempt, plan summary, dependencies, pending decisions, next wake, cancellation revision and observation deadline. These records, rather than a chat transcript or heartbeat alone, say what must happen next.
4. **Execution:** exact request and operation IDs, provider acceptance, tool receipts, lease/fencing generation, checkpoint and result digest. A resumed worker cannot repeat an ambiguous external effect simply because it cannot see an acknowledgement.
5. **Learning:** candidate lessons, scope, supporting and contradicting outcomes, evaluation receipt and adopted revision. An agent may improve an authorized operating method; it cannot turn a self-written reflection into a wider permission or proven customer result.

Source records remain authoritative. Search indexes, embeddings, summaries and prompt context are derived projections. Correction, revocation or deletion must invalidate derived retrieval and future use; retention records may preserve an allowed minimal audit fact without keeping erased content. Sensitive cross-business learning is off by default. Organization-wide lessons require appropriate source scope; an employee's private material is not automatically business memory.

A sleeping agent remains employed. Work wakes from a relevant event, completed dependency, scheduled commitment or observation deadline. Idle seats do not make model calls merely to appear alive. Wakeups are coalesced, rate-limited, budgeted and durably recorded. Duplicate events resolve to the same intent. No progress or repeated failures trigger backoff and a visible stop or reassignment within policy, not endless self-messaging.

Execution resumes by recovering the durable intent, comparing any existing result/effect receipt, acquiring a current fenced lease, revalidating policy/source/resource authority and dispatching only the remaining admitted operation. A lost provider acknowledgement stays in reconciliation until its state is established. External exactly-once effects cannot be promised for an API without suitable idempotency or reconciliation. Stopping a business revokes new effects; already accepted external effects may need a separately recorded compensating action.

Concurrency is permitted across independent Work. One current lease owns each mutable attempt/resource; duplicate workers cannot both commit. Team messages use durable inbox/outbox records with sender identity, destination audience, correlation, acknowledgement and expiry. Read-only FYI messages should not automatically wake the whole company. High-priority dependency messages can wake an assigned seat, with cycle and fanout bounds. Meetings and chats stay useful collaboration surfaces, not the authority for scheduling and spend.

Portable continuity means the business can export its own records, source references, decisions, work and employment configuration in documented formats, subject to source rights and retention rules. Remote providers may not expose proprietary state or tools. The export must distinguish portable state from unavailable vendor internals and validate missing dependencies on import.

## Entrepreneurs and control

Onboarding presents two clear starting modes:

- **I run the company:** the human is CEO. Agents propose priorities, execute delegated responsibilities and bring selected decisions to that person.
- **The team runs it:** an agent operator acts as CEO within a standing business mandate. The owner supplies the objective, resources, success measures and reserved decisions, then receives an operating report and can intervene.

The organization creator chooses a clear organization-wide authority preset, including **full autonomy**. Suggested presets are advise, execute assigned work, take initiative, and full autonomy; plain-language examples explain what each permits. The chosen level is a ceiling that role/team mandates may narrow. Full autonomy delegates prioritization, initiation, delegation, review and execution across granted resources and funded limits without routine human approval. It is a real operating mode, not a renamed approval queue. Changing the ceiling is an owner-authorized policy revision; the operator cannot raise its own ceiling or infer access to unconnected resources. The creator may appoint additional administrators through the organization's explicit ownership/access process.

Both modes use the same underlying decision mandates. They are onboarding presets, not separate products or one global autonomous toggle. A human CEO may fully delegate engineering and retain pricing. An agent CEO may run product and marketing while the owner reserves new commitments above a budget threshold. A completely agent-operated business is allowed for the actions the owner has granted; no human confirmation is inserted into every step.

Decision authority is assigned per class: choosing priorities, allocating existing budget, creating artifacts, updating owned resources, publishing, contacting external people, purchasing and changing organizational access. Each class binds actor, resource scope, budget, duration and review requirement. Agent-to-agent review is valid when the mandate allows it. Required independent review records actual provider/family independence and cannot silently degrade when a route is unavailable. People can replace or dismiss the operator without losing the company.

Mode changes increment policy revision, show a concrete rights diff and invalidate unissued effects. In-flight actions revalidate before their next external effect. Takeover pauses future autonomous decisions immediately; the UI shows already accepted external actions separately. Offboarding revokes grants, cancels or reassigns commitments, retains business-owned history under retention policy, and removes vendor access. Forking an employment creates a new principal and only copies an explicitly selected, authorized state snapshot; forks do not inherit credentials or spend rights.

## Setup and product surface

A short setup asks: what are we building or operating; who is the customer; what would a useful first result be; who will run it; what resources and budget can it use. STRIDE proposes the smallest appropriate team and first milestone. The owner reviews a concrete operating mandate expressed in business language, including what the team can do immediately and what remains unavailable. Templates reduce setup, but do not invent market demand or connect resources without consent.

Start from connected existing systems where possible. Required resources are requested just in time for a specific job, showing account, permissions, intended effect and cost. A plan can be drafted before all integrations exist; missing delivery access is visible. Preview mode has explicit sample data and cannot look like operating revenue.

The main experience has five connected views:

- **Business:** objective, customers, outcome measures, available budget, latest decisions, progress and next action.
- **Team:** human/agent roles, reporting lines, capabilities, active commitments, availability, spend and observed performance.
- **Work:** deliverables, environments, execution progress, dependencies, exact results and review evidence.
- **Memory:** searchable business knowledge with source, correction, audience and learned operating methods.
- **Conversations and rooms:** direct human/agent discussion, rich media and reliable calls, attached to the business and its work.

A decision inbox contains only decisions assigned to the viewer or unresolved outside the team's mandate. Agent-led businesses should not appear stuck behind a human-review inbox by default. The activity record gives a concise explanation of what changed and why, with inspectable evidence, rather than streaming every agent token. Show cost and actual outcomes separately. Phone supports decisions, communication and result inspection; tablet and desktop support richer work and operating views.

## Initiative from conversations and calls

Founder explicitly requests agents that notice ideas while people talk, discard weak ones and act on valuable opportunities without waiting for a direct instruction. This is a first-class initiative source. It is enabled for a visible participating agent or disclosed business observer, under the room's current audience and capture policy. Membership alone does not authorize ambient access to private calls. Existing participants must be able to see who or what can observe; a call's source audience remains authoritative when an agent proposes work elsewhere.

Treat existing transcription, analysis and agent meeting presence as unproven prototypes, per the founder's explicit instruction. Reuse is conditional on measured capability, not code existence. Establish audio capture/transport continuity, transcript accuracy and latency under overlap/noise/accent conditions, diarization and speaker correction, reconnect continuity without duplicate utterances, authorized retention, actual useful insight and reliable participation. The baseline includes browser, iPhone and iPad with real devices and network changes. A displayed transcript, tile or simulator pass is not acceptance.

Inspect the existing meeting/transcript intake, source-bound recall and Work proposal seams for reuse or replacement. Do not run another media owner or put model deliberation on the audio/video critical path. Provisional captions stay provisional; use stable transcript segments and conversation windows with speaker/source references. Continuous speech must not generate a model call per token. A bounded observer coalesces events, deduplicates ideas and can wait for the discussion to resolve itself. Observe-only, suggest, and act-within-mandate are understandable participation settings.

The initiative path is **observe → candidate → value check → discard, defer, investigate or act → observe outcome**. Each candidate records source IDs/versions, business objective fit, whether the need is already being handled, expected benefit, uncertainty, likely effort/cost, timing, destination and the exact action it could take. These are estimates, not invented financial returns. Discard is a normal successful decision. Keep minimal deduplication state with a bounded lifetime; do not turn every passing idea into permanent company memory or a backlog item.

Speech is evidence of a discussion, not a privileged instruction channel. Distinguish a direct assigned request from a suggestion, joke, quoted request, disagreement and speculative brainstorming. An external document or participant utterance cannot enlarge the observer's mandate. Check current source, actor, destination and policy before prompt admission and again before an effect. If the conversation changes direction, supersede the candidate; do not keep executing a stale hypothesis because the first transcript sounded confident.

The operator may autonomously conduct a small private investigation, draft an artifact, compare alternatives, open an internal Work item, or deliver an already authorized external action. The exact mandate determines which actions are available. Missing authority can yield a concrete proposal or a hold; it need not discard useful analysis. Assign only one owner to overlapping initiatives, cap concurrent speculative work and total observation/initiative spend separately, and attach the evidence to the resulting Work.

Examples: two people repeatedly discuss onboarding confusion; the agent checks authorized evidence and prepares a short improvement proposal with one prototype. A pricing idea may prompt a private comparison; publishing new prices requires an existing pricing mandate. A repeated unresolved question may cause targeted research. A passing wish with no objective fit can be discarded without notifying anyone. Disagreement can be preserved as uncertainty and trigger inquiry; it is not silently promoted into company policy.

Default call behavior is quiet: queue useful results for a natural pause or post-call brief, and interrupt only under the room's notification rules for an assigned question or a consequential time-sensitive issue. A visible initiative inbox/activity view shows what an agent picked up, why, cost and outcome, with stop/dismiss/reassign controls. A user's dismissal suppresses repeated versions of the same suggestion for the defined scope and duration. A fully delegated business can let its operator review that queue itself.

Measure accepted useful initiatives and actual outcomes, intervention/annoyance, speculative spend, duplicate work, time saved and effects of missed opportunities. Neither candidate count nor agent message volume is success. Test disagreement, corrections after launch, revoked meeting access, silence, long calls, duplicate transcript delivery, concurrent agents, business budget exhaustion, interruptions and media latency before rollout. Begin with disclosed observation and private draft actions; expand to each already defined external-action mandate after its adapter is qualified.

## Integrations and deployment

STRIDE owns identity, authority, budget reservation, durable commitments and result provenance. Provider adapters own model execution, with actual wire identity recorded. Qualified isolated execution adapters own code/tool runtime. OAuth service grants and resource proxies bind actions to the correct business; credentials are never placed in a persona prompt.

Use native APIs/webhooks for reliable external effects; MCP adapters for supported tools and resources; A2A adapters where independently hosted agents expose compatible task lifecycles. Protocol support is not proof of isolation, authorization or durable receipt behavior. Each adapter needs versioned capability, cancellation, retry, idempotency, data egress and cost contracts. No adapter may bypass existing Work or grant checks. Existing agents can join a business without requiring their complete internal implementation to move into STRIDE.

Offer hosted operation first. Architect identity and execution placement separately so a business can later use its own model account, dedicated executor or private environment. Do not make all those enterprise deployment modes launch prerequisites. BYO provider keys change billing and data flow; they do not bypass platform limits or make the execution service free. Initial deployments reuse existing infrastructure and qualified providers.

## Business model and incentives

Working hypothesis: subscription per operating business with included platform capacity, plus transparent metered execution and optional specialist service fees. Human seats and dormant agent identities should not be the primary meter: the value is operating continuity and delivered work. Concurrency, retention and dedicated execution may define higher tiers. Exact prices require actual cost and willingness-to-pay evidence.

Avoid revenue-share billing initially: attributing business revenue to a particular agent intervention is difficult, and a success fee could reward misleading attribution. Marketplace fees are appropriate only once third-party services, refunds, support and evidence standards are real. A future public performance profile can show publisher capability evidence or owner-approved achievements without exposing company data. No automatic public resume is built from private work.

Business operating money and STRIDE service billing are distinct accounts. A model-token budget is not permission to purchase advertising, accept commercial terms or move customer funds. The product may later execute those functions through exact resource-specific mandates and integrations; the initial operator proof spends only its explicitly funded model allowance.

## Human contribution protocol

The founder and cofounder explicitly request evidence that lets agents and people evaluate the contribution of human collaborators, including whether human involvement is useful for a particular job. Treat this as a protocol over actual work, with people and agents assessed on comparable evidence. It must not become a universal person-value score or a private-context social ranking.

A contribution receipt binds `subjectPrincipalId, actorKind, businessId, workRootId, attemptIds, resultRevision/digest, contributionType, action/sourceRefs, evaluatorPrincipalId, evaluatorRouteRevision, assessment, outcomeRefs, evidenceClass, limitations, visibility, consentRevision, supersedesId`. Contribution types include originating an idea, supplying missing context, creating an artifact, changing a decision, identifying an error, testing an assumption, and coordinating delivery. Preserving a useful dissent counts even if a team ultimately chooses another direction. Record the exact intervention and resulting change, not inferred merit from job title, speaking time, message count or tokens.

Separate three layers: attribution (who did what), assessment (what an evaluator believes it contributed), and outcome (what actually happened). A signed receipt proves its issuer and integrity, not the truth of its claims. A model's confidence is not causal evidence. Counterfactual comparisons may estimate marginal value only with disclosed task/context/model/tool/budget differences and uncertainty; withholding a person's insight in a synthetic replay is not a controlled market experiment. Team contributions need not sum to a forced100percent or assign one winner.

For matching, start with a task's required capabilities, context and constraints. Offer relevant, current receipts showing why this person or agent could help. An agent operator may select a collaborator under its business mandate and available resources; qualification concerns the task, not personal worth. Do not infer hiring suitability from unrelated private conversations, protected characteristics or speculative personality profiling. Sparse evidence remains unknown. Do not create a global hidden denylist or automatically turn a negative model assessment into a portable adverse employment decision.

Subjects can inspect the evidence and evaluator identity, provide missing context, challenge an assessment and append a correction. Disputed or superseded assessments remain visibly qualified and do not silently return through old indexes. Allow an independent review route for contested consequential evaluations. Measures must resist gaming, self-awarded credit, reciprocal praise and evaluator collusion. Evidence of prevented mistakes should identify the observed defect and fix; estimated losses avoided remain estimates.

Private organizational receipts stay scoped to their original sources. Publishing a portable profile requires subject participation and appropriate company/source release, with field-level selective disclosure, expiry/revocation and verification. A public receipt can disclose an approved work outcome without exposing its underlying private document. Publishers cannot export another employer's confidential memory. Importers recheck current receipt status and evidence limits rather than trusting a cached star rating.

Product surface: a contribution trail on a Work result, an individual's inspectable record of relevant work, and a task-specific collaborator recommendation with reasons and uncertainty. Human and agent profiles both show observed performance, context, costs where meaningful, and outcomes. Avoid the incentive to produce more activity or erase collaborators because model execution looks cheaper in a poorly matched benchmark.

Business implication: this can become the portable work identity layer beyond a resume, and a useful discovery surface for human experts and specialist agents. Develop an open, versioned receipt format once the internal semantics are proven; hosting, execution and trusted workflow integration remain product services. A marketplace and public ranking are not prerequisites. Do not sell personal assessments or silently use private workplace data to build a commercial reputation graph.

Public identity decision (founder follow-up): public profiles are an optional portfolio of work, collaborators, evidence and outcomes for people, agents and businesses. The primary positioning remains the place where agents build and operate businesses. Discovery earns a separate entry point only after real, permissioned work exists; a social feed and connection counts are not the initial acquisition strategy. A profile should answer what this collaborator can help build, with inspectable examples, contribution context, current availability and a clear invitation to work together. Showcase the actual artifact and the business outcome with exceptional typography, media treatment and phone/tablet performance. Separate verified evidence, self-authored narrative, evaluator inference and unavailable/private evidence. No empty capability claims, synthetic reputation or universal scores.

Publication is a deliberate release operation over selected receipt fields and artifact revisions, requiring the contributor and relevant source owner's authority. A public profile can exist without making any private organization discoverable. Corrections and withdrawals propagate to hosted profiles and verification endpoints; independently copied public material cannot be promised remotely erased. Contact and collaboration requests need audience controls, rate limits and consent. Organizations keep private operational memory; profile matching receives only the permitted subset. The first implementation should prove one excellent public case study and its correction/withdrawal lifecycle before expanding into a network or hiring marketplace.


First proof: a person catches a real flaw in agent work; exact intervention changes the result; the eventual outcome is recorded; an independent evaluator explains the contribution and limits; the person corrects or contests a mistaken assessment; an explicitly released minimal receipt verifies elsewhere and can be revoked. Also demonstrate a human intervention that did not improve the result without converting that episode into a general judgment of the person. Existing `stride_contribution_authority.go` is explicitly route-free/body-free policy code; it is a prototype reference, not a working protocol.

## Current gaps, sequence and proof

Repo evidence: `stride_workforce_runtime.go` explicitly describes its roster as an offline lifecycle ledger and issuance as fenced; it is not an executing workforce. `goal_engine.go` persists plan and context checkpoints, but these rely on current legacy authority and do not establish service-principal employment. Existing usage telemetry is not a durable pooled budget. W4 authority stores are single-process and current legacy work data is not isolated for a second live organization. The disabled code runner cannot be renamed autonomous execution.

Revised implementation choice after direct source inspection: build a tenant-native transactional PostgreSQL Business/Work kernel inside the receipted application. Organizations, memberships, employments, mandates, reservations and Work in the new namespace share one authority/transaction domain. Existing stable authenticated Person identity is a temporary login adapter; W4 JSON organization membership is not mirrored or treated as permission for this namespace. The workspace chooser routes opaque IDs to the correct owner without exposing engine internals. Legacy Bonfire Work remains on its original owner until an explicit migration. This supersedes the earlier cloned-engine-cell proposal: local identity locks, singleton media/background startup and fixed service inventories make that approach an expensive compatibility project without proving a business.

Implementation sequence: ship Business binding recognition while dispatch remains off; establish isolated Builders identity/data and current grants; add durable employment/mandate/budget/launch intents; bind an existing private authored Work process; add event-driven supervision and observation; prove two episodes with restart and policy changes; qualify any external effect adapter before allowing its specific action. The existing execution engine is a candidate, not a mandatory foundation. Qualify its restart, authority and effect semantics against the business proof; replace it if another durable runtime is materially better, with a deliberate migration and one authoritative execution owner. Preserve the exact release path unless its replacement also proves identity, observation and rollback. Do not accidentally create a second informal background agent service.

The required initiative proof starts with a disclosed real-device call in which people discuss one useful opportunity and one weak or joking idea, with no direct “do this” request. The agent quietly launches useful authorized Work and discards the weak candidate. The run survives restart and a source correction, delivers an exact result, records its actual outcome and uses that observation to choose the next episode. Measure call quality, interruptions and speculative cost alongside the work result. A manually launched brief alone cannot satisfy this proof.

Acceptance scenarios must cover process death after provider acceptance, duplicate wakeups, lease loss, no billing while idle, expired/changed policy, source correction/revocation, exhausted budget, unpriced call, vendor outage, offered-agent update, human takeover, offboarding and cross-organization hiring isolation. The same business should operate in both leadership presets using the same records. A capability package migration must preserve commitments and fail if requirements cannot be met. Financial and customer outcomes must show observation provenance and uncertainty.

For AJ now: existing account/provider/repository/deployment access supports continued build and bounded QA; no new credential request is justified yet. A recurring autonomous STRIDE service needs a concrete continuing resource allowance and an activated mandate after isolation and durable budgeting exist. Prepare that exact proposal rather than asking for an arbitrary budget before it can operate. Private-device media testing and account-owner ceremonies may still need AJ when the exact build/action is ready. No claim that this Codex task has already become a persistent STRIDE employee.

## Alternatives and why not now

- One immortal conversational thread per agent: simple demo, unreliable authority, memory and restart semantics.
- One shared learned persona across customers: potential reuse, unacceptable implicit mixing of company state. Reuse packages and authorized general methods instead.
- Open marketplace first: many listings, no proof a business runs. Start curated and demonstrate continuity.
- Model-specific employee identity: straightforward implementation, fragile to model retirement and poor routing flexibility.
- Per-agent seat billing as primary model: familiar subscription unit, discourages specialist collaboration and misprices idle identities.
- Immediate replacement of the engine with a new orchestration framework: possible future option, unjustified migration before existing exact Work/state seams are proven insufficient.

## Primary-source context

[OpenAI Frontier](https://openai.com/business/frontier/) already describes shared business context, production agent execution and learning/evaluation. These are competitive baseline capabilities; our proposed distinction requires actual operated-business evidence.

[Temporal event history](https://github.com/temporalio/documentation/blob/main/docs/encyclopedia/event-history/event-history.mdx) documents durable history and replay as a recovery approach. This supports the architectural distinction between persisted execution and conversational memory; it is not a decision to migrate the STRIDE engine to Temporal.

[A2A specification](https://a2a-protocol.org/v0.3.0/specification/) describes discoverable capability cards and task interaction, with authorization implemented by the service. Use it as a candidate adapter contract, never as evidence that a remote agent is already authorized or reliable.
